Journal des envois

Ce que le flux DEVRAIT envoyer, message par message (D.envoisJournal). Sert au support autant qu’à l’idempotence — l’expédition, elle, n’est pas branchée.

HorodatageCanalModèleObjetDestinataireRéfÉtat
Aucun message à envoyer — le journal se remplit avec les événements réels (compte créé, vente, paiement d’une marque…).
Un destinataire à la fois. Un message qui porterait à la fois une marque et un commerce serait lu par les deux — donc une fuite de données entre audiences. La seule exception est la diffusion d’équipe côté manager : un arrêté dû ne s’adresse à personne en particulier.
Push et notification dans l’app se doublent, ils ne se remplacent pas. Le push attire l’attention et disparaît ; le fil de l’app reste consultable. Un commerce qui a refusé les permissions de notification ne doit jamais perdre l’information pour autant.
